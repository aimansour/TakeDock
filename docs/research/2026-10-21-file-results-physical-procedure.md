# File result and rename physical acceptance procedure

This procedure uses the previously authorized wireless phone connection. Leave
ADB pairing and the server running. Use only new test recordings created for
this trial, and keep the private journal and backups outside tracked evidence.

1. Record the source commit/tree, release executable hash, Android helper hash,
   ADB version and connected ABI. Snapshot the app settings and Android
   accessibility configuration. Record unrelated video identities and hashes
   privately without publishing filenames or device identifiers.
2. Start the release executable with NVDA already running. Through ordinary
   recording controls create two short test clips, journal the exact paths
   against the before/after listing, stop normally and wait for finalization.
   Pull each new clip to a private backup, compare SHA256 with the phone and
   decode the entire local video using ffmpeg before any rename/delete. This
   verification is trial tooling and is never added to product capture/delete.
3. In Videos select one backed-up trial clip. Rename it using the native form.
   Check the source checkbox remains selected, exposes the new computed name,
   retains its actual DOM node, and passes its refreshed identity to a later
   copy. Check readiness and duration match a fresh read-only listing.
4. Keep the success Hide button unfocused. Observe its ten-second common
   lifetime in two UI-opened windows and its retained details in initially
   collapsed history. An additional window opened after expiry must not
   replay the success. Confirm passive retirement does not move focus.
5. Create a no-overwrite rename collision using only the two backed-up trial
   clips. Preserve both hashes. Its failure remains after a later clean
   success expires. Hide it through a native button in one window and observe
   acknowledgement in the other. If its Hide button is focused, that card
   stays until focus leaves. Explicit local hide may return focus to another
   Hide button or the history summary, unless the user already moved focus.
6. Check English/Arabic native labels and ordinary history text. No live
   announcement, synthesized speech or extra completion sound belongs to
   result refresh, acknowledgement or expiry. Ask the user for audible NVDA
   observations; computed names and focus alone do not certify speech.
7. Record monotonic capture observations during file work and expiry alongside
   an unchanged-path baseline. Deterministic held-worker/warning cases remain
   in the hosted external fixture; never disrupt phone media services to
   manufacture those failures.
8. Restore temporary app/accessibility settings. Verify unrelated identities
   and hashes, preserve all private trial backups, and confirm the authorized
   wireless connection still appears as `device`. Publish only sanitized
   observations with distinct native, backend and audible evidence levels.

Execution and final hashes are recorded separately when the final product tree
has passed its hosted gates. This document alone is not a passing test report.
