## Review Focus

1. EOF or input failure leaves a small buffered tail: exact data must flush successfully before stream completion, while an error must discard that tail without drop-time retries; test in Task 3.
2. Cancellation holds a sub-buffer-size prefix while a later batch file is valid: join before partial cleanup, retain the source and preserve normal later-file handling; test in Tasks 3–4.
3. A trace write fails, clocks disagree or an observation misses an expired result: invalidate measurement instead of inventing a fast completion or changing product behavior; test in Tasks 1–2.
4. A duplicate filename/old manifest points at a replacement, a path escapes the trial or settings change during the run: refuse mutation/restoration against the wrong object; test in Task 2.
5. Only the phone hash gets faster, while total UI time regresses or a Move loses acknowledgement: reject the performance claim and preserve truthful outcomes; test in Tasks 2, 4–5.

### Timing and benchmark contracts

Add Cargo feature `transfer-diagnostics = []`, off by default. It changes observation only, never chooses serial/parallel behavior. `transfer_trace` supplies crate-private `Trace`, `TraceKey { job_id: String, generation: u64, file_index: Option<usize> }`, `Stage`, `Edge { Mark, Begin, End }`, `Tick = u64`, and:

```rust
Trace::from_env() -> Trace
Trace::stamp(&self) -> Tick
Trace::record_at(&self, key: &TraceKey, stage: Stage, edge: Edge, tick: Tick)
Trace::mark(&self, key: &TraceKey, stage: Stage, edge: Edge)
Trace::complete_job(&self, key: &TraceKey)
```

Stages are `Accepted`, `Enqueued`, `Worker`, `Prepare`, `InitialStat`, `Stream`, `Sync`, `StoredSize`, `PostTransferStat`, `Verify`, `RemoteHash`, `LocalHash`, `Publish`, `MoveStat`, `Delete`, `Index`, `Terminal`. Capture the accepted tick at entry to `FileService::start_job`, attaching it to the allocated ID only after successful validation. Capture the `Enqueued` tick immediately before `try_send` and record it only if submission succeeds, so a fast worker cannot produce a negative queue interval. Mark worker start before helper preparation, and authoritative `Terminal` after classification and before the existing terminal sink call. Preserve matching span ends on errors. Concurrent trace order is determined by ticks, not append order.

With the feature and `TAKEDOCK_TRANSFER_TRACE` set to a fresh absolute private path, one process-owned bounded writer receives `try_send` records and writes one stream header plus a completion footer for each job. Capacity is 256 records; overflow/write failure marks the trace incomplete and cannot block/fail a file job. With the feature absent, the interface is a zero-state no-op: no environment lookup, clock, allocation or writer. Keep stage records free of filenames/serials/addresses. Header includes schema `1`, clock kind/frequency and process correlation; edges include job ID, generation, file index, stage/edge and decimal-string ticks. After the terminal sink returns, `complete_job` queues a footer request; the writer flushes prior edges and that job's footer, including dropped count and writer status. A missing/bad job footer invalidates its measurement; do not depend on graceful process shutdown to flush evidence. Hosted tests may inspect incremental edges during a held job, then validate its footer after release. The reader validates complete jobs rather than requiring the process to exit.

On Windows the trace clock uses `QueryPerformanceCounter`/`QueryPerformanceFrequency`, via small checked `kernel32` FFI behind the feature. PowerShell uses `[Diagnostics.Stopwatch]::GetTimestamp()` and `Frequency`; require matching frequencies and monotonic ordered boundaries. This is a shared-host interval clock, not UTC. See [Microsoft's QPC/Stopwatch guidance](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps). Non-Windows diagnostic tests may use a process-relative `Instant` clock explicitly labelled `process_relative`; such records cannot be combined across processes for UI timing.

PowerShell modules export these interfaces; they return hashtables/objects, not new application IPC:

- Core: `Read-TransferTrial -Manifest <path> -TrialRoot <path>` returns a validated trial; `Get-TransferVerdict -Runs <object[]> -UncertaintyMs <double>` returns `{accepted, groups, reasons}`; `Read-TransferTrace -Path <path> -JobId <string>` validates complete spans/correlation and returns header/edges/job footer; `Join-TransferRun -UiResult <object> -Trace <object>` computes the final run record below.
- Device: `New-TransferFixture -SeedVideo <path> -TargetBytes <long> -Output <path>`; `Prepare-TransferTrial -TrialRoot <path> -AdbPath <path> -Serial <string> -Seeds <string[]>`; `Assert-TransferSource -Trial <object> -FixtureId <string>`; `Complete-TransferTrial -Trial <object>`. Device functions call the supplied real ADB directly, without an ADB proxy.
- UI: `Open-TransferSession -Executable <path> -DriverUri <uri>`; `Invoke-TransferRun -Session <object> -Trial <object> -Run <object>` returns `{run_id,job_id,kind,bytes,build,ui_start_ticks,ui_end_ticks,observation_uncertainty_ms,outcome}`; `Close-TransferSession -Session <object>`. Use native WebDriver element actions; read-only existing `bootstrap`/`file_results` may correlate IDs, never initiate a mutation.
- Runner: `scripts/measure-transfer.ps1 -TrialRoot <path> -Manifest <path> -Builds <json-path> -Stage Baseline|Compare -AdbPath <path> -TauriDriver <path> -EdgeDriver <path> -FfmpegPath <path> -FfprobePath <path>`. Resolve/verify the supplied media tools before any device mutation. Builds JSON names immutable executable/resource hashes and source revisions for `released`, `baseline` and later `candidate`.

Trial schema `1` contains a trial GUID; canonical local root/destination/backup paths; private device identity; exact fixture remote name, full opaque identity, payload size/SHA-256, verified backup and decode receipt; unrelated-file baseline; current settings/accessibility baseline; and an append-only run journal. A run names build, size, kind, pair/order, warm-up flag, fixture ID, unique empty destination and correlation ID. Never infer ownership from a `VID_` prefix or filename alone.

The final run record extends the UI result with `pair: int`, `order: int`, `warmup: bool`, `backend_ms: double|null`, `ui_ms: double`, `stages: hashtable`, `valid: bool` and `invalid_reason: string`; exact byte counts and ticks remain decimal strings. `backend_ms` spans accepted-to-terminal, `ui_ms` spans native action-to-matching notice, and terminal-to-visible delay is calculated on the verified shared clock. Uninstrumented released-build calibration has a null backend duration and no trace; it may quantify UI overhead, but cannot enter the baseline/candidate verdict. That verdict requires complete successful measured records in all four groups and both metrics for each pair.

### Active stream-copy contract

The private `files::stream_copy` module exposes only `copy_exact<R: Read, W: Write, P: FnMut(u64)>(reader: &mut R, writer: &mut W, expected_size: u64, progress: P) -> Result<(), String>`. Its fixed input and write buffers are 256 KiB each. Successful return establishes exact EOF and an explicit successful final flush; error exit consumes/discards buffered state without an implicit drop-time write/retry. The existing child controller, cancellation flags, inactivity limit, joins and serial verification remain unchanged. No `VerificationControl`, `verify_pair`, new verification worker or error translation is introduced under the approved buffering amendment. Leave `hash_path` unchanged.
